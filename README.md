# Introduction to Mutation Testing

**Disclaimer:** This code is deliberately contrived to demonstrate mutation testing. Special cases, such as Unicode text handling and stack overflows from deep recursion, are intentionally excluded from the tests to keep the examples easy to understand.

## Step 3

In Step 3, we have added a test for the missing branch: the first and last characters match, but the middle is not a palindrome. An example word is "polyp", whose middle is "oly". Please take a look at the new test [`MorePalindromeTest.cs`](TestPalindrome/MorePalindromeTest.cs).

With the .NET 10 SDK and ReportGenerator from Step 2 installed, run the following in PowerShell from the repository root. Clear only the previous test results and coverage report, leaving mutation reports untouched. This runs all seven tests and generates the coverage report:

```powershell
foreach ($directory in 'artifacts\TestResults', 'artifacts\coverage') {
  if (Test-Path -LiteralPath $directory) {
    Remove-Item -LiteralPath $directory -Recurse -Force -ErrorAction Stop
  }
}
dotnet test `
  Palindrome.sln `
  --collect:"XPlat Code Coverage" `
  --results-directory artifacts\TestResults
reportgenerator `
  "-reports:artifacts\TestResults\*\coverage.cobertura.xml" `
  "-targetdir:artifacts\coverage" `
  "-reporttypes:Html"
```

Open `artifacts/coverage/index.html` in a browser. All seven tests pass, and Coverlet now reports 100% line and branch coverage.

So, we are done? Not so fast! This is where mutation testing comes in to show us if our tests are adequate. A mutation testing tool like [Stryker.NET](https://stryker-mutator.io/docs/stryker-net/introduction/) will introduce bugs in our code, and see if our tests catch them. The bugs are called mutations, and if the tests fail, the tests are successful in catching the bug, and so the mutation is killed. However, if the tests pass, the mutation survives (which is not a good thing).

If Stryker.NET is not already installed, install it once:

```powershell
dotnet tool install --global dotnet-stryker --version 5.1.0
```

On Windows ARM64 only, first run `$env:PlatformTarget = 'ARM64'` in the same PowerShell session to avoid Stryker requesting an x64 test host. From the repository root, clear only the previous mutation results and run Stryker, leaving the coverage report untouched:

```powershell
if (Test-Path -LiteralPath 'artifacts\stryker') {
  Remove-Item -LiteralPath 'artifacts\stryker' -Recurse -Force -ErrorAction Stop
}
dotnet stryker `
  --solution Palindrome.sln `
  --output artifacts\stryker
```

On macOS or Linux, use PowerShell and `/` instead of `\` in the command paths.

Open `artifacts/stryker/reports/mutation-report.html` in a browser. This report is generated by the Stryker command, not the coverage command above. Stryker.NET 5.1.0 kills nine of ten tested mutants, a mutation score of 90%. Despite full code coverage, one mutation survives. Let us explore and fix this.

If you dig further, you will find that not all mutations were killed by tests. We are clearly missing a test condition. When `word.Length < 2` is changed to `word.Length <= 2`, no tests fail. We have not tested the exact boundary at length 2.

Leave your browser with the mutation testing results up, and move to Step 4.
